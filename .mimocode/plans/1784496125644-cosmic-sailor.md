# Connectify Comprehensive Audit & Optimization Plan

## Project Overview

**Stack:** React 19 + Vite + Tailwind CSS v4 + Express backend (in-memory JSON DB)
**Type:** Social media SPA with AI chatbot integration (OpenRouter API)
**Architecture:** Single-file server (`server.ts` ~1700 lines) + SPA frontend (~14 component files)

---

## Phase 1: Critical Security Fixes

### 1.1 Authentication Overhaul
**Files:** `server.ts` (auth routes), `src/components/AuthModal.tsx`

- **No password validation:** Login accepts any password without checking (`server.ts:472-488`). Password is received but never compared.
- **No password hashing:** Registration stores plaintext password (which is never stored at all - password field is ignored in user creation at line 438-450).
- **Mock JWT tokens:** Tokens are `jwt-mock-token-{userId}` - trivially forgeable. Any user can impersonate another.
- **Fix:** Implement bcrypt password hashing, proper JWT with secret, and real token validation middleware.

### 1.2 API Authorization Middleware
**File:** `server.ts`

- **No auth middleware:** Every endpoint trusts `userId` from request body. Any user can act as any other user.
- **Profile edit endpoint** (`POST /api/users/profile`) accepts arbitrary `userId` - any user can edit any profile.
- **Fix:** Add JWT verification middleware that extracts `userId` from token, not from request body.

### 1.3 Input Sanitization
**Files:** `server.ts` (all POST routes)

- No XSS sanitization on user content (post content, comments, bio, username).
- No input length validation on server side.
- `username` only strips spaces (`replace(/\s+/g, "")`) - allows special characters.
- **Fix:** Add server-side input sanitization (strip HTML tags, limit lengths), validate username format.

### 1.4 Security Headers & CORS
**File:** `server.ts`

- CORS is `Access-Control-Allow-Origin: *` - allows any origin.
- No rate limiting on any endpoint.
- 50MB body limit is excessive.
- **Fix:** Restrict CORS, add rate limiting middleware, reduce body limit, add helmet-style security headers.

## Phase 2: Performance Optimization

### 2.1 Reduce Polling Frequency
**File:** `src/App.tsx`

- `fetchPeriodicData` polls every **5 seconds** (line 111) - notifications, stories, AND recommendations simultaneously.
- Messages component polls every **3 seconds** (line 128).
- **Fix:** Increase intervals to 15-30 seconds, implement conditional polling (only when tab is active), add `visibilitychange` listener.

### 2.2 Optimistic Updates Consistency
**Files:** `src/components/Feed.tsx`, `src/components/Explore.tsx`, `src/components/Profile.tsx`

- Like reactions do optimistic update but then fully replace with server response (line 478-479 in Feed.tsx).
- Bookmark handler mutates `currentUser.bookmarks` directly (line 746) instead of using `setCurrentUser`.
- **Fix:** Standardize optimistic update pattern, use proper state updates.

### 2.3 Image Optimization
**Files:** All components with `<img>` tags

- No `loading="lazy"` on any images.
- No `width`/`height` attributes causing layout shifts (CLS).
- Unsplash images fetched at default size without explicit sizing parameters.
- **Fix:** Add lazy loading, explicit dimensions, use Next-gen formats where possible.

### 2.4 Bundle & Code Splitting
**Files:** `src/App.tsx`, `vite.config.ts`

- No lazy loading of route components - entire app loaded upfront.
- `Feed.tsx` is ~1300 lines, `Explore.tsx` ~1100 lines - should be split.
- **Fix:** Add `React.lazy()` for tab components, split large components.

### 2.5 Remove Global Fetch Interceptor
**File:** `src/main.tsx`

- Global `window.fetch` monkey-patching (lines 7-46) runs on every fetch call.
- **Fix:** Use a centralized API client utility instead of patching global fetch.

## Phase 3: Code Quality & Architecture

### 3.1 Extract API Client
**New file:** `src/lib/api.ts`

- Every component has its own `fetch()` calls with repeated patterns (content-type headers, error handling, response parsing).
- **Fix:** Create a centralized API client with:
  - Base URL configuration
  - Auth token injection
  - Response type safety
  - Error handling
  - Content-type checking (currently duplicated in every component)

### 3.2 Extract Custom Hooks
**New files:** `src/hooks/usePosts.ts`, `src/hooks/useAuth.ts`, `src/hooks/useMessages.ts`, etc.

- Post fetching, liking, commenting logic duplicated across Feed, Explore, Profile components.
- Auth state management scattered in App.tsx.
- **Fix:** Extract reusable hooks for common operations.

### 3.3 Split Large Components
**Files:** `Feed.tsx` (~1300 lines), `Explore.tsx` (~1100 lines), `Profile.tsx` (~947 lines)

- Feed.tsx contains PostMedia, feed item rendering, comments, sharing, polls, story generation.
- **Fix:** Extract into separate files: `PostCard.tsx`, `PostMedia.tsx`, `CommentSection.tsx`, `ShareModal.tsx`, `PollDisplay.tsx`.

### 3.4 Server-Side Code Organization
**File:** `server.ts` (~1700 lines)

- All API routes, database logic, seed data, AI integration in one file.
- **Fix:** Split into: `routes/auth.ts`, `routes/posts.ts`, `routes/users.ts`, `routes/messages.ts`, `routes/stories.ts`, `lib/db.ts`, `lib/ai.ts`, `middleware/auth.ts`.

### 3.5 TypeScript Strictness
**File:** `tsconfig.json`

- Missing `strict: true`, `noUncheckedIndexedAccess`, `noUnusedLocals`.
- `skipLibCheck: true` hides type issues.
- **Fix:** Enable strict TypeScript checks, add proper return types.

### 3.6 DRY: Remove Duplicated Patterns
- `formatPostTime` / `formatNotifTime` / `formatStoryTime` - same logic in 3 places.
- Content-type JSON checking duplicated in every fetch call.
- Verified badge rendering duplicated in ~15 places.
- **Fix:** Create shared utility functions and a `VerifiedBadge` component.

## Phase 4: UI/UX Improvements

### 4.1 SEO & Meta Tags
**File:** `index.html`

- Title is "My Google AI Studio App" - not Connectify.
- No meta description, Open Graph tags, Twitter cards, favicon.
- **Fix:** Add proper meta tags, OG image, description, favicon.

### 4.2 Responsive Design Fixes
**Files:** `Messages.tsx`, `Feed.tsx`, `Sidebar.tsx`

- Messages panel is fixed 1/3 width (line 206) - breaks on mobile.
- Sidebar hidden on mobile but no hamburger menu or bottom nav.
- Filter buttons overflow on small screens.
- **Fix:** Add mobile navigation, make Messages responsive, improve filter overflow handling.

### 4.3 Empty States & Error Boundaries
**Files:** All components

- No React Error Boundaries - any component crash kills the entire app.
- Some empty states exist but are inconsistent.
- **Fix:** Add ErrorBoundary wrapper, standardize empty state designs.

### 4.4 Accessibility Improvements
**Files:** All components

- Buttons lack `aria-label` attributes.
- Modal dialogs don't trap focus.
- No keyboard navigation support for custom dropdowns.
- Color contrast issues with `text-gray-400` on light backgrounds.
- Images missing meaningful `alt` text.
- **Fix:** Add ARIA attributes, focus trapping in modals, keyboard navigation, improve contrast.

### 4.5 Animation Accessibility
**File:** `src/index.css`, various components

- No `prefers-reduced-motion` support despite using animations.
- **Fix:** Add `@media (prefers-reduced-motion: reduce)` to disable animations.

### 4.6 Form Validation UX
**Files:** `AuthModal.tsx`, `PostCreate.tsx`, `Settings.tsx`

- No client-side validation before submission.
- Password field has no minimum length requirement.
- Post content limit (2200) not visually indicated.
- **Fix:** Add real-time validation, character counters, password strength indicators.

## Phase 5: Production Readiness

### 5.1 Environment Configuration
**Files:** `.env.example`, `vercel.json`

- `vercel.json` proxies to a hardcoded Cloud Run URL - not configurable.
- No `.env.local` setup documented.
- **Fix:** Make backend URL configurable via env vars, document setup.

### 5.2 Error Handling & Logging
**Files:** `server.ts`, all frontend components

- Server errors only logged to console.
- Client errors only `console.error` - no user-facing error recovery.
- No structured logging.
- **Fix:** Add proper error responses, toast notifications for failures, structured logging.

### 5.3 Database Resilience
**File:** `server.ts`

- JSON file DB can corrupt on crash during write.
- No backup strategy.
- In-memory arrays lose data on server restart if db.json is corrupted.
- **Fix:** Add atomic file writes, backup before overwrite, consider SQLite.
